# 破壊的変更

前のバージョンから更新したときに、そのままでは同じように動かなくなる変更を、バージョンごとにまとめます。
更新する前に、今のバージョンより後のバージョンに書いたことをすべて読み、書いてある対処を済ませてください。
更新の手順は[運用](operations.md#更新)にあります。

## v2026.11.6

v2026.11.5からの変更です。

### ルールから外れた予約を、放送の直前でもすぐ消す

どのルールにも一致しなくなったルール予約を、放送の直前でも、次の照合ですぐ消すようにしました。今までは、放送の3時間前を過ぎた予約と、番組名が空の番組の予約を、消さずに録っていました（v2026.11.4から）。ルールの条件を書き換えて外したのに、外したはずの番組を録ってしまうからです。

- 管理者の録画の既定値の画面（`/admin/recording`）から、「ルールから外れた予約を残す時間（放送前の分）」の欄を外しました。変えていた値は使わなくなります。GraphQLの`SystemSettings.ruleUnmatchedGraceMinutes`と、`updateSystemSettings`の同じ名前の入力も外しました。
- 番組表から消えた番組の予約は、予約に残した番組名、概要、詳細、ジャンルで、ルールに照合し直します。一致すれば今までどおり残し、ルールを書き換えて外れていれば消します。今までは、ルールに関わらず残していました。
- 番組表の直前の書き換え（[新]が付く、サブタイトルが入るなど）で外れた予約も消えます。番組が条件に戻れば、次の照合で予約し直します。録り逃したくない番組は、キーワードを書き換えに強い形（番組名の一部だけにする、など）にしてください。

### `-ffmpeg`イメージのFFmpegを、自分でビルドしたものにする

`-ffmpeg`イメージのFFmpegを、Debianの`ffmpeg`パッケージ（7.1）から、リリースのtarballからビルドした9.1に替えました（#2001）。KotatsuとGoのテストが使う部品だけを組み込んでいます。

- Kotatsuの使い方（放送のTSの変換、サムネイル、CMの区間の見分け、字幕の自動生成）では、対処は要りません。
- `ffmpeg`と`ffprobe`の置き場所は、`/usr/bin`から`/usr/local/bin`に変わりました。イメージを土台にして、パスを書いたスクリプトを動かしているときは、修正してください。
- 放送で使わない形式（AC-3やMP3の音声、ほかの映像のコーデック、HTTPの入力など）は扱えません。イメージの`ffmpeg`を、Kotatsuのほかの用途に使っていたときは、別のFFmpegを用意してください。
- NVENCを使うときのNVIDIAのドライバの下限は、今までと同じLinuxで530.41.03以降です。

### 重複の回避で、映像か音声にドロップのある録画を録画済みとみなさない

重複の回避で「録画済み」とみなす録画を、映像と音声のPIDのドロップが上限以下のものに改めました。上限は管理者が「設定」→「録画の既定値」の「ルールの照合」にある「録画済みとみなす映像・音声のドロップの上限（件）」で変えられ、既定は0件です。今までは、全PIDのドロップが4件以下の録画を録画済みとみなしていました。

- 更新した後に録り終えた録画のうち、映像か音声に1件でもドロップのあるものは、録画履歴に記録しません。同じ番組の再放送があれば、ルールに従って録り直します。今までと同じく4件まで許すときは、上限を4にしてください。
- 字幕やデータ放送、番組情報のPIDだけのドロップは数えないので、BS4Kの録画の多くは、今までどおり録画済みになります。
- 更新する前に記録した録画履歴は、そのまま残ります。

### 端末ごとに保存していた設定の一部を、端末をまたいで同期する

キーとゲームパッドとマウスの割り当て、CMの自動スキップ、番組表の見た目と28時間表記、ヘッダーのロゴなど、端末ごとに保存していた設定の一部を、端末をまたいで同期するようにしました（#1862）。同期する設定の一覧は、[設計書](spec.v1.md)の9.1にあります。

- 更新した後、各端末で最初に開いたときに、サーバーにまだない設定は、その端末の値をサーバーへ引き継ぎます。サーバーに先に引き継がれた値があれば、その値を使います。
- そのため、端末ごとに違う値にしていた設定は、最初に開いた端末の値にそろいます。端末ごとに変えていた設定は、そろった後で選び直してください。

### 照合で、波ダッシュとダッシュの類を`~`と`-`にそろえる

番組名などを照合するときに、波ダッシュ（`〜`）を`~`に、ダッシュの類（`‐`、`–`、`—`、`―`、`−`など）を`-`にそろえるようにしました（#2041）。キーワードに`〜`と書いても、`～`と書いた番組に一致するようになります。

- 正規表現のキーワードで、`〜`やダッシュの類を書いていたら、`~`と`-`に書き換えてください。正規表現は、そろえた後の文字列に当てるので、そのままでは一致しなくなります。
- 正規表現でないキーワードは、書き換えなくても一致します。
- 更新した後の最初の`kotatsu migrate`は、これらの文字を含む番組や録画の検索用のカラムを書き直すので、番組表の大きさによっては、いつもより長くかかります。
- v2026.11.5までのバイナリは、更新した後のDBでは起動しません。古いバイナリは、書き直したカラムと照合して、一致しなくなったルール予約を消すからです。

## v2026.11.5

v2026.11.4からの変更です。

### 機能の設定を、設定ファイルから管理者の画面に移す

設定ファイルと環境変数には、起動とインフラに要るものだけを残し、機能と外部の連携に関わる次の項目は、管理者の画面で変えるようにしました（#1869）。
更新した後は、設定ファイルや環境変数に書いた値を読みません。今の値も引き継がず、どれも既定値に戻ります。

| 前の項目（環境変数） | 既定値 | 変える画面 |
| --- | --- | --- |
| `audit.retention_days`（`KOTATSU_AUDIT_RETENTION_DAYS`） | 365日 | 「設定」→「保持期間」の「監査ログ」 |
| `audit.client_info_retention_days`（`KOTATSU_AUDIT_CLIENT_INFO_RETENTION_DAYS`） | 90日 | 「設定」→「保持期間」の「監査ログ」 |
| `auth.hibp.enabled`（`KOTATSU_AUTH_HIBP_ENABLED`） | 照会しない | 「設定」→「連携」の「漏れたパスワードの確認」 |
| `web_push.subject`（`KOTATSU_WEB_PUSH_SUBJECT`） | KotatsuのリポジトリのURL | 「設定」→「連携」の「Web Pushの送り手」 |
| `thumbnail.disable_preview`（`KOTATSU_THUMBNAIL_DISABLE_PREVIEW`） | プレビュー画像を作る | 「設定」→「録画の既定値」の「後処理」 |
| `power.manage_sleep`（`KOTATSU_POWER_MANAGE_SLEEP`） | スリープを扱う | 「設定」→「録画の既定値」の「OSのスリープ」 |
| `captions.threads`（`KOTATSU_CAPTIONS_THREADS`） | 0（CPUの数の半分。1〜8） | 「設定」→「録画の既定値」の「後処理」 |
| `jikkyo.channels`（`KOTATSU_JIKKYO_CHANNELS`） | 同梱の対応表だけ | 「設定」→「サービス」の「ニコニコ実況のチャンネル」 |

- 既定値から変えていたときは、更新した後に、管理者が画面で設定し直してください。とくに、監査ログの保持期間を既定より長くしていたときは、更新した後の最初の片付け（nekonoteが起動したときと、1日ごと）で、365日より古い記録が消えます。消したくなければ、更新する前にDBをバックアップするか、更新してすぐに画面で長くしてください。
- 設定ファイルや環境変数に残していても、Kotatsuは起動します。起動するときに、無視した項目と変える画面をログで警告します。警告が出なくなるよう、設定ファイルと環境変数から消してください。
- `captions.whisper_command`、`captions.whisper_model`、`captions.vad_command`、`captions.vad_model`、`auth.hibp.url`は、設定ファイルと環境変数に残しています。

### 録画履歴のキーとドラマの作品名のキーを作り直す

重複の回避に使う録画履歴のキーが、囲み文字のテーブルにあるマークの一部（`[4K]`、`[HDR]`、`⚿`など）を取り除いていなかったので、取り除くようにしました（#1977）。
ドラマの作品名も、`作品名 season 2. request 20. サブタイトル`のような番組名で、シーズンの番号まで削っていたので、`作品名 season 2.`と読むようにしました（#1978）。

- 更新するときの`kotatsu migrate`が、録画履歴のキーと、ドラマの番組の結びつきの作品名のキーを、番組名から作り直します。管理者の上書きは、前のキーから今のキーにコピーします。対処は要りません。
- 作り直すまでは、古いバイナリが前の読み方で書いた行が残ることがあります。ローリング更新の間に書いた行は、次の`kotatsu migrate`で直ります。
- 番組表にもアーカイブにもない番組でしか使っていなかったドラマの上書きは、コピーできないので前のキーのまま残ります。その作品の番組がまた放送されて結びつかなかったら、番組の詳細の「作品を直す」で決め直してください。

### QSVでも、VAAPIのデバイスの設定を使う

QSVのエンコーダー（`kyusu.encoder: qsv`）でも、映像の復号と縮小をVAAPIでするようにしました（#1999）。使うGPUは、`kyusu.vaapi_device`（`KOTATSU_KYUSU_VAAPI_DEVICE`、既定は`/dev/dri/renderD128`）で選びます。

- GPUが1つだけのマシンでは、対処は要りません。
- GPUを複数持つマシン（NVIDIAのGPUを足したものなど）では、`/dev/dri/renderD128`がIntelのGPUでないことがあります。QSVを使っているなら、`kyusu.vaapi_device`にIntelのGPUのデバイス（`/dev/dri/renderD129`など）を設定してください。どれがIntelのGPUかは、`/dev/dri/by-path`のリンクの先か、`vainfo --display drm --device <デバイス>`のドライバーの名前（Intel iHD）で分かります。

### 処理が追いつかない端末と、回線が足りないときは、画質を自動で下げる

画質のメニューに「自動」を足し、画質を選んでいない端末では「自動」にしました（#1513）。「自動」では、映像の処理が追いつかない端末で、画質を1段ずつ下げます。回線が足りないときも、届く速さに収まる画質へ下げ、ライブで最も低い画質でも足りなければ、音声だけにします。オリジナル（この端末で変換）からはkyusuの画質へ移すので、kyusuを動かしている環境では、サーバーでのエンコードが増えることがあります。

- 処理が追いつかずに下げた画質より上へは、タブを開いている間は戻しません。読み込み直すと、元の画質から始めます。
- 回線のために下げた画質は、回線の余裕を確認してから1段ずつ上げます。ライブでは、そのためにtenbanのプローブのデータ（`/internal/streams/probe`）を取ります。ほかの配信と同じくセッションのCookieで受け付けるので、リバースプロキシなどで`/internal/streams/*`を通していれば、構成を変える必要はありません。
- 前と同じく画質を動かさないときは、プレイヤーの「設定」の「画質」で、オリジナルや720pなどを選んでください。選んだ画質は、端末ごとに保存します。前に画質を選んだことのある端末は、選んだ画質のまま動かしません。

### 1080iの放送を59.94pで表示する

ブラウザ内での変換で再生するとき、1080iの放送を、フィールドごとに1コマにして59.94pで表示するようにしました（#1655）。前は29.97pでした。動きはなめらかになりますが、描画の負荷は倍になります。

- 表示が追いつかない端末では、再生の途中で自動で29.97pに戻します。
- 前と同じ表示にするときは、「設定」→「プレイヤー」で「1080iをフィールドごとに表示する」を切ってください。端末ごとの設定です。

### 外部プレイヤーとIPTVのクライアントのURLは、管理者が有効にしたときだけ使える

外部プレイヤー（VLC、mpvなど）用の署名付きURLと、IPTVのクライアント（Kodi、Jellyfin、Plexなど）用のURLは、持っている人なら誰でも使えます。
漏れたときの影響を小さくするため、どちらも、管理者が有効にしたときだけ発行し、受け付けるようにしました（#1755）。既定は無効です。

- 更新すると、発行済みの外部プレイヤー用のURLと、IPTVのクライアントに登録したURLは使えなくなります。
- 使い続けるときは、管理者が「設定」→「連携」で「VLCやmpvで開くURLを発行する」と「KodiやJellyfinで見るURLを発行する」を有効にしてください。有効にすると、取り消していないIPTVのURLは、発行し直さなくても、また使えるようになります。
- 外部プレイヤー用のURLは、URLごとに記録して取り消せるよう、署名の形を変えました（#1757）。更新する前に発行したURLは、有効にしても使えないので、画面から発行し直してください。
- 録画の詳細の「ダウンロード」と「端末に保存」は、この設定と関係なく使えます。

### 外部プレイヤー用のURLの期限が変わる

外部プレイヤー用のURLの有効期限を、一律の6時間から、見るものの長さに合わせた長さに変えました（#1756）。録画は録画の長さに1時間を足した長さ、ライブは発行から1時間です。5時間より短い録画とライブでは、前より短くなります。

- ライブのURLを、発行から1時間より後に開き直すときは、画面から発行し直してください。期限の前に開いたストリームは、期限を過ぎても流れ続けます。

### ブラウザ以外から叩くエンドポイントのパス

前段に認証のプロキシ（Authentikのforward-authなど）を置く構成で、認証から外すパスを`/api`、`/.well-known`、`/oauth`、`/mcp`、`/healthz`の5つにまとめられるよう、ブラウザ以外から叩くエンドポイントを`/api`の下に移しました（#1605）。古いパスは使えなくなり、転送もしません。

| 変わったもの | 前のパス | 新しいパス |
|---|---|---|
| EPGStation互換のAPI | `/api/*` | `/api/epgstation/api/*` |
| 予約のカレンダー（iCalendar） | `/calendar/<秘密の値>/reservations.ics` | `/api/calendar/<秘密の値>/reservations.ics` |
| ライブ視聴の一覧（M3U）と番組表（XMLTV） | `/iptv/<秘密の値>/…` | `/api/iptv/<秘密の値>/…` |
| 外部プレイヤー用の署名付きURL | `/streams/services/…`、`/streams/recordings/…` | `/api/streams/services/…`、`/api/streams/recordings/…` |

- EPGStation互換のAPIを使うクライアント（kiririnなど）は、ベースURLを`https://<ホスト>/api/epgstation`に変えてください。
- 予約のカレンダーと、IPTVのクライアントに登録したURLは、パスを上のテーブルのとおりに直してください。秘密の値は変わらないので、発行し直す必要はありません。
- 外部プレイヤー用のURLは、画面から発行し直してください。前のバージョンで発行したURLは使えなくなります。
- 画面のプレイヤーが使う`/streams/*`と`/media/*`は、署名付きURLを受け付けなくなり、セッションのCookieでだけ認証します。
- 前段に認証のプロキシを置いているときは、`/api`の下を認証から外してください。`/calendar`、`/iptv`を認証から外す設定は、要らなくなります。

### 画面が使うエンドポイントのパス

画面がセッションのCookieで使うエンドポイントを、`/internal`の下に移しました（#1605）。古いパスは使えなくなり、転送もしません。

| 変わったもの | 前のパス | 新しいパス |
|---|---|---|
| GraphQL | `/graphql` | `/internal/graphql` |
| ログイン、ログアウト、WebAuthn、OIDC | `/auth/*` | `/internal/auth/*` |
| 映像の配信 | `/streams/*` | `/internal/streams/*` |
| 画像、実況のコメント、キャプチャ | `/media/*` | `/internal/media/*` |

- OIDCでログインしているときは、IdPに登録したリダイレクトURIを、`/auth/oidc/callback`から`/internal/auth/oidc/callback`に書き換えてください。書き換えるまでは、OIDCでログインできません。設定の`auth.oidc.redirect_url`（`KOTATSU_AUTH_OIDC_REDIRECT_URL`）を書いているときは、その値も書き換えてください。
- AnnictとAniListとの連携を使っているときは、それぞれのアプリに登録したリダイレクトURIを、次のとおりに直してください（#1906）。どちらも、管理者の画面の「設定」→「連携」の「Annict、AniListへの記録」に出ます。直すまでは、連携をつなぎ直せません。つないである連携は、そのまま使えます。
  - Annict：`/auth/anime-records/annict/callback`から`/internal/auth/annict/callback`へ。Annictのアプリの一覧（`https://annict.com/oauth/applications`）で、登録したアプリのリダイレクトURIを書き換えます。
  - AniList：`/auth/anime-records/anilist/callback`から`/internal/auth/anilist/callback`へ。AniListの開発者の設定（`https://anilist.co/settings/developer`）で、登録したクライアントのRedirect URLを書き換えます。
- リバースプロキシで、パスごとに転送先や設定を分けているときは（実況のWebSocketを通す設定など）、`/internal`の下に合わせてください。
- 更新した直後は、ブラウザに残った前のバージョンの画面が、古いパスを呼んで失敗することがあります。画面を読み直してください。

### Tailscaleのアドレスからの接続は、既定では受け付けない

接続元の既定の許可から、Tailscaleが使う`100.64.0.0/10`を外しました（#1758）。この範囲は、tailnetを共有した相手や、同じISPのCGNAT（RFC 6598の共有アドレス空間）の中からも届くためです。

- 接続元の設定をせずに、Tailscale経由で使っているときは、更新するとつながらなくなります。`server.allowed_external_networks`（`KOTATSU_SERVER_ALLOWED_EXTERNAL_NETWORKS`）に`100.64.0.0/10`を書いてください。書き方は[設定](configuration.md)にあります。

### 接続元の設定を、家の中と外の2つの項目に分けた

`server.allowed_networks`（`KOTATSU_SERVER_ALLOWED_NETWORKS`）を、家の中のネットワークの`server.allowed_private_networks`（`KOTATSU_SERVER_ALLOWED_PRIVATE_NETWORKS`）と、家の外のネットワークの`server.allowed_external_networks`（`KOTATSU_SERVER_ALLOWED_EXTERNAL_NETWORKS`）に分けました（#1759）。家の中のネットワークは、RFC 1918、ループバック、IPv6のユニークローカルとリンクローカルです。インターネットやTailscaleから受け付けるのは危険を伴うので、家の中の範囲とは別の項目に書かせ、書き間違いや、意味を知らずに広げてしまうことを防ぐためです。

- `server.allowed_networks`が残っていると、起動しません。書いていた範囲を、家の中の範囲は`server.allowed_private_networks`へ、それ以外（`0.0.0.0/0`、`::/0`、`100.64.0.0/10`など）は`server.allowed_external_networks`へ移してください。
- 家の中の範囲を書き直さずに、家の外の範囲だけを足すなら、`server.allowed_external_networks`だけを書けば足ります。

### 録画のダウンロードは、管理者が有効にしたときだけ使える

録画の詳細の「ダウンロード」（録画を1つのTSファイルとして保存する機能）は、録画をKotatsuの外へ持ち出す機能なので、管理者が有効にしたときだけ使えるようにしました（#1762）。既定は無効です。

- 使い続けるときは、管理者が「設定」→「連携」で「録画をファイルとしてダウンロードさせる」を有効にしてください。
- 端末に保存（オフラインで見る機能）は、この設定に関係なく使えます。

### EPGStation互換のAPIは、管理者が有効にしたときだけ提供する

EPGStation互換のAPI（`/api/epgstation/api/*`）は、APIトークンを持っている人なら誰でも、ライブと録画の映像を読めます。そのため、管理者が有効にしたときだけ提供するようにしました（#1769）。既定は無効です。

- kiririnなどのEPGStation互換のクライアントで使っているときは、更新するとつながらなくなります（404）。管理者が「設定」→「連携」で「EPGStation互換のAPIを提供する」を有効にしてください。発行済みのAPIトークンは、発行し直さなくても、また使えるようになります。
- 無効の間は、APIトークンを新しく発行できません。発行済みのトークンは、取り消せます。

### 選局を拒否された録画の失敗の理由を分けた

チューナーサーバーが選局を断った録画（チャンネルかサービスがない404と、選局に失敗した500）の失敗の理由を、`tuner_unavailable`から新しい`tuning_refused`に分けました（#1519）。チューナーの空きがない（503）録画と、応答を待ちきれなかった録画は、これまでどおり`tuner_unavailable`です。

- 録画の失敗のWebhookの`reason`と、`/metrics`の`kotatsu_recording_failures_total`の`reason`に、`tuning_refused`が出るようになります。`tuner_unavailable`で絞って見張っていたなら、`tuning_refused`も足してください。
- 更新する前に失敗した録画の理由は、変えません。

### Helm Chartのコンテナに、既定でrequestsとメモリのlimitsを付ける

Helm Chartで、`resources`を書いていないロールとマイグレーションのJobに、CPUとメモリのrequestsと、メモリのlimitsを付けるようにしました。値は[設計書の11.1](spec.v1.md#111-配布物)のテーブルのとおりです。

- 今までは上限がなかったので、limitsを超えるメモリを使っていたロールは、更新するとOOMKillで再起動を繰り返します。とくに、同時に多くの変換を動かすkyusuと、大きなモデルで字幕を生成するnekonoteは、使っている量を確認し、足りなければ`roles.<ロール>.resources.limits.memory`（`all`の構成では`all.resources.limits.memory`）を上げてください。
- ノードの空きがrequestsに足りないと、Podが置かれずPendingになります。
- valuesの`resources`を書いていても、書かなかった項目には既定値が入ります（Helmはvaluesを深くマージします）。既定値を外すときは、`memory: null`のようにnullを書きます。

## v2026.11.4

v2026.11.3からの変更です。

### 同じ回のまとめ

- ルールに「局をまたいで同じ回をまとめ、最初の放送だけを予約する」設定を足しました（#1498）。録画済みの回と、同じ回の2回目以降の放送を予約しません。
- 更新する前からあるルールは切のままなので、動きは変わりません。画面で新しく作るルールと、見たいリストの候補から作るルールは、既定で入になります。
- `kotatsu import epgstation`は、「重複を避ける」を付けていたルールで、この設定も入れます。
- 新しく作るルールで切にしたいときは、管理者が録画の既定値の画面（`/admin/recording`）の「ルールを作るときの既定値」で切ってください。
- この設定を入れたルールの予約の録画は、録り始めに放送のEIT[p/f]で番組情報を書き直し、同じ回を録画済みと分かれば録画をやめます（#1500）。やめた録画は録画の一覧に残らず、予約は「同じ回を（局名）で録画済みなので録画しない」として無効になります。録りたいときは、予約の画面で有効に戻すか、手動で予約し直してください。

### 録画の変換のコマ数

- 録画の変換（#1253）で出すコマ数を、自動、30、60から選べるようになり、既定は自動になりました（#1509）。自動では、変換の前に録画の映像を計測し、実写（60i）と見分けた録画を、これまでの30コマではなく60コマで変換します。アニメやフィルム（24p）と30pの録画は、これまでどおり30コマです。
- 録画の変換を使っている（録画の既定値、ルール、予約のどれかで画質を選んでいる）ときは、更新した後に変換する実写の録画で、変換の時間が延び、MP4が大きくなります（合成の映像では、CPUの時間が1.8倍、MP4が1.4倍でした）。どの録画も、変換の前に計測する分（40秒ほど）だけ、変換の始まりが遅れます。
- これまでどおり30コマで出したいときは、管理者が録画の既定値の画面（`/admin/recording`）の「変換のコマ数」で「30コマ/秒」を選んでください。ルールと予約でも選べます。
- 変換を使っていなければ、対処は要りません。

### WindowsとmacOSのスリープ

- WindowsとmacOSで`kotatsu all`を動かすと、録画、ライブ視聴、エンコードの間と次の録画の直前は、OSがスリープしなくなりました。次の録画の5分前には、スリープから起こす予約を置きます（#1522）。
- タイムシフトを有効にしたサービスがあると、ずっとスリープしません。
- 起こす予約は、Windowsではタスク スケジューラのタスク（`\Kotatsu\Wake`）として登録し、管理者の権限が要ります。macOSではrootが要ります。権限が無ければ、起動した後に1回だけ警告を出し、スリープさせないことだけを行います。
- これまでどおりOSに任せるときは、設定の`power.manage_sleep`（`KOTATSU_POWER_MANAGE_SLEEP`）を`false`にしてください。

### 条件なしのルール

- ルールには、含めるキーワード、チャンネル種別、サービス、ジャンル、含める囲み文字のどれかが要るようになりました。時間帯と曜日、長さ、無料放送、除外の条件だけのルールは、その時間の全局を録ってディスクを埋めるからです（#1501）。
- 更新すると、そうしたルールは何も予約しなくなります。作り済みの予約は消さずに残り、放送まで録ります。nekoのログには、ルールごとに1回、`skipped a rule without a keyword, channel type, service, genre, or mark`の警告が出ます。
- 引き続き使うには、ルールの編集画面で、チャンネル種別やサービスなどの条件を足してください。条件を足すまで、そのルールは保存できません。
- `kotatsu import epgstation`は、そうしたルールを取り込まず、dry runの計画の「Skipped」に数を出します。

### 重複の回避で録画済みとみなすドロップ

- 重複の回避で「録画済み」とみなす録画を、ドロップが1件以下から4件以下に広げました（#1497）。BS4Kの録画は、本番ではすべてに3〜4件のドロップが出ていたので、これまでは録画済みにならず、同じ番組を録り直していました。
- 更新した後に終わった録画から効きます。更新する前の録画は、録画履歴に入っていないので、録画済みとみなしません。

### ルールから外れた予約

- どのルールにも一致しなくなったルール予約でも、放送の3時間前を過ぎていれば、消さずに録るようになりました。番組表の直前の書き換えで外れた予約を消して、録り逃さないためです（#1501）。番組表にあるのに番組名が空の番組の予約も、消さずに録ります。
- ルールの条件を変えても、3時間の内に始まる番組は、変える前の条件のまま録ります。ルールを消すか無効にしたときは、これまでどおり、すぐに予約を消します。
- これまでどおり、すぐに消したいときは、管理者が録画の既定値の画面（`/admin/recording`）の「ルールの照合」で、時間を0にしてください。

### 実況のコメント

- 実況は既定では使わなくなりました。外部のサービスと通信するので、管理者とユーザーの両方が有効にしたときだけ使います。
- 更新すると、全体の設定で実況が無効になり、ライブ視聴と録画の再生で実況のコメントが出なくなります。
- 引き続き使うには、管理者が連携の画面（`/admin/integrations`）で、コメントのソースのNX-Jikkyoを有効にしてください。
- プレイヤーの設定を一度も変えていないユーザーは、ユーザーの設定でも無効になります。各ユーザーがプレイヤーの設定の画面（`/settings/player`）か、プレイヤーの実況のボタンで有効にしてください。プレイヤーの設定を変えたことがあるユーザーは、実況を有効にしていれば、その設定を引き継ぎます。

### ライブの実況の中継

- ライブ視聴の実況のコメントは、ブラウザがNX-Jikkyoへ直接つながず、tenbanがプロキシするようになりました。ブラウザは同じオリジンのWebSocket（`/media/jikkyo/{channel}/ws`）につなぎます。
- リバースプロキシを通すときは、WebSocketの接続を通すようにしてください。通さないと、ライブ視聴で実況のコメントが流れません。nginxでは次のヘッダーを設定します。

  ```nginx
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection $connection_upgrade;
  ```

  `$connection_upgrade`は、`http`のブロックで定義します。

  ```nginx
  map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
  }
  ```

- tenbanからNX-Jikkyo（`nx-jikkyo.tsukumijima.net`）へ通信できるようにしてください。外部への通信を制限している環境では、tenbanからの通信を許可します。

### 録画の再生位置の保持期間

- 録画の再生位置に、保持期間を設けました。最後に更新してから365日を過ぎた再生位置は、nekonoteが消します。
- 更新してnekonoteを起動すると、すぐに1回目を実行します。365日より前に更新したきりの再生位置は、そのときに消えます。
- 消したくないときは、`kotatsu migrate`でスキーマを更新した後、nekonoteを起動する前に、保持期間を0（無期限）にしてください。保持期間はDBの設定です。保持期間の画面（`/admin/retention`）で変えるには、tenbanだけを先に起動します。`all`の構成のように、tenbanとnekonoteを分けて起動できないときは、DBで次のSQLを実行します。

  ```sql
  UPDATE system_settings SET watch_progress_retention_days = 0;
  ```

### 監査ログのIPアドレスとUser-Agentの保持期間

- 監査ログのIPアドレスとUser-Agentに、保持期間（`audit.client_info_retention_days`、`KOTATSU_AUDIT_CLIENT_INFO_RETENTION_DAYS`）を設けました。既定は90日です。過ぎた記録はIPアドレスとUser-Agentだけを空にし、操作の記録は残します。
- 更新してnekonoteを起動すると、すぐに1回目を実行します。90日より前の記録のIPアドレスとUser-Agentは、そのときに空になります。
- もっと長く残すには、新しいバージョンを起動する前に、この設定を大きくしてください。上限はなく、`audit.retention_days`以上にすれば、監査ログを消すまで残ります。古いバージョンは、設定ファイルに知らないキーがあると起動しません。新しいバージョンに切り替えるまでは、設定ファイルではなく環境変数で渡してください。

### `X-Forwarded-Host`と`server.allowed_hosts`

- `X-Forwarded-Host`に値が複数あるとき、すべての値を`server.allowed_hosts`で確認するようになりました。これまでは、最左の値だけを確認していました。
- 信頼済みのプロキシがヘッダーを上書きせずに追記する構成（Apacheのmod_proxyの既定など）で、`server.allowed_hosts`を設定しているときは、どのプロキシが追記するホスト名も`server.allowed_hosts`に書いてください。書かないと、リクエストを拒みます。

### OTLPで送るトレース

- OTLPで送るトレースから、視聴者のIPアドレスとUser-Agentの属性（`client.address`、`network.peer.address`、`user_agent.original`など）を除くようになりました。
- `url.path`は、先頭の2つのセグメントだけを残し、後ろのセグメントと数字を含むセグメントを`:id`にまとめます。
- これらの属性で絞り込むダッシュボードやアラートは、作り直してください。
